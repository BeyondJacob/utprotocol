⏺ Thank you for the clarifications! Let me explain init containers briefly, then proceed with implementation.

  Init Containers Overview

  Init containers are containers that run to completion before the main application container starts. They're useful for:
  - Running database migrations
  - Waiting for dependent services to be ready
  - Setting up configuration files
  - Pre-populating data

  In docker-compose, you can achieve this with:
  1. depends_on + healthchecks: Wait for a service to be healthy before starting
  2. Separate service: A one-time container that runs migrations then exits
  3. Entrypoint script: Run migrations in the main container's startup script

  For this project, I'll use approach #3 (entrypoint script in the backend) since it's simplest and ensures migrations run every
  time the backend starts.
